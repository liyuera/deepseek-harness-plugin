# 轻量规格 · Bug 看板改版为「流程泳道 B」

> 目标：把右栏看板从「平铺列表 + 详情」改为**阶段泳道**：窄栏=阶段分组卡片流，宽栏=横向泳道；卡片直接回答「卡在哪/等谁/等了多久/下一步」，详情加流程步骤条。只改表现层与交互，不改宿主接口/状态机/存储/子代理。

- **范围**：`bug-workflow/client.js`（列表/详情/筛选概览/阶段映射）+ 新增 `test/client-stage-map.test.js` + 设计文档。设置页与 token 卡保持现状（仅随主题令牌走）。
- **状态→泳道映射**（唯一数据源，marker 字面量，测试锁定）：`inbox→草稿`；`analyzing→分析中`；`plan_review→方案待审`；`fixing→修复中`；`fix_done→待人工测试`；`submitting→交付中`；`mr_open/fixing_review→Review 中`；`mergeable/merged→等你合并`；`blocked→需要处理`；`done` 不展示。
- **响应式**：容器宽 <720px → 垂直阶段分组（默认右栏）；≥720px → 横向泳道（横向滚动 + 阶段概览 chip 定位）。用 `ResizeObserver` 监听容器宽，纯前端本地状态。
- **卡片**：编号/类型/标题 + 元信息（版本、改动文件数、耗时）+ **下一步 chip**（等你审核/等你测试/等你合并/AI 运行中/阻塞原因）+ 等待时长（人工态）或已运行时长（AI 态，来自 snapshot.running + updatedAt 估算）；AI 运行态脉冲点；点击进详情。
- **概览条**：每个泳道计数 chip（可点：筛选该阶段/滚动定位），「需要你」泳道优先排序并高亮。
- **详情**：顶部加 7 步流程条（同步→分析→方案→修复→测试→交付→Review/合并，当前步高亮，阻塞时红点）；其余方案/修复/测试/MR/时间线卡片保持现有功能与文案。
- **不做**：拖拽推进（P2 再做，需宿主状态机二次校验）、AI 副驾对话、文档式排版、字体/图标/新依赖；不新增接口；不改 `ACTION_BY_STATE` 字面量。
- **边界/反例**：空列表/筛选无结果/未绑定工作区/服务未接线必须有明确空态；`done` 不出现；已知 `blocked` 出现在「需要处理」泳道且给出原因文案；窄栏卡片不横向溢出；键盘可达（卡片是 button，`aria-current` 保留）。
- **验收**：`node --check client.js`；`node --test test/*.test.js` 全绿（新增 stage-map 契约测试）；`node scripts/e2e-delivery.mjs` 不受影响；GUI 刷新后人工验收窄栏/宽栏/明暗主题（我无法截图桌面端，需你确认）。
