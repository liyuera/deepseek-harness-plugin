**为什么不在本轮清理**：
- 看板没有删除/归档 API；宿主正在运行并持有 domain，任何直接改 storage 文件都会被内存状态覆盖或与并发写竞争——任务要求不得手改 live storage，因此**不能安全清理**。
- 清理需要退出 DSH，而用户不在场、本轮不允许重启/关闭 app。
- 删除会让 P3 失去现成 demo 数据，收益有限；保留的代价只是 3 条过期外链。

### 7.3 清理 recipe（已实现脚本，本轮只在副本上验证）

新增 `bug-workflow/scripts/cleanup-demo-tickets.mjs`（默认 dry-run，`--write` 才写）：

```sh
# 1) dry-run：只打印，不改文件
node bug-workflow/scripts/cleanup-demo-tickets.mjs \
  --codes YGFNXDJRFWDJSYJJYY-647,YGFNXDJRFWDJSYJJYY-648,HTSMART-12

# 2) 完全退出 DSH 后，再执行写入
node bug-workflow/scripts/cleanup-demo-tickets.mjs \
  --codes YGFNXDJRFWDJSYJJYY-647,YGFNXDJRFWDJSYJJYY-648,HTSMART-12 --write
```

安全设计：

- 只接受 `source === 'platform'` 且 `platform.url` 为 loopback（`127.0.0.1`/`localhost`/`::1`）的工单；manual 工单或真实平台 URL 一律拒绝（本轮验证：`DEMO-1` → REFUSE，exit 1，文件不变）。
- 写前校验 JSON/`unit.name==='bug_workflow'`/`unit.version≥1`/`tables.tickets`；任何不合法直接退出，不碰文件。
- 先记录原文件的 mtime/size；`--write` 时再次 stat，若读取后文件被改动则拒绝写入，避免覆盖并发/宿主写入。
- 写序：同目录复制 `0600` 备份 `<storage>.bak-<timestamp>` → `wx` + `0600` 临时文件写入 → `fsync` → 重新 parse 校验 → 原子 `rename` → 对新文件 `chmod 0600`；失败时清理临时文件。
- **rename 之后的失败语义**：chmod 或回读校验失败时，新文件已经就位（原文件已被替换），脚本会打印备份路径和「已被替换」，不再声称「Original file untouched」。
- 只删 `tables.tickets[code]`；`meta` 的 `action:` 幂等账本原样保留（孤儿项无害，账本上限 500 条）。
- **不 reset** settings / `platform.lastSyncAt` / `platform.lastSyncError`；如需「干净」状态，删票据后可用真实平台成功同步一次，或手写 settings（不涉及 token）。

本轮副本验证（`/tmp/p2t6/cleanup-test/bug_workflow.json`，从 live 复制，`0600`）：

### 10.1 Critical：同步 upsert 与本地动作的写竞争（已修复）

- **问题（已复现）**：store 没有任何写串行化。`upsertPlatformRecords()` 先读旧工单、拼出 clone，再 `await tickets.put()`；`applyAction()/create()` 同样是读-改-写。把 upsert 的 put 暂停 → 执行 `start_analysis`（写入 `analyzing`）→ 放行 upsert → 工单被旧 clone 覆盖回 `inbox`，timeline 只剩 `created`，动作静默丢失。自动同步（600s）、按编号导入和第二块看板都让这条路径可达，P3 的 plan 写入同样会中招。
- **修复（`src/host/store.js`）**：新增 store 级 promise 链写队列 `withWrite(fn)`；`create` / `applyAction` / `upsertPlatformRecords` / `putSettings` / `setMeta` / `setDicts` 全部入队，整个读-改-写（含 actionId 账本查/写）在临界区内完成；内部改为 `*Unlocked` 帮助函数，`applyAction('create')` 调 `createUnlocked`、`setDictsUnlocked` 调 `setMetaUnlocked`，避免自锁；读方法（`list/get/snapshot/getSettings/getMeta/getDicts`）保持无锁。写链尾在失败后仍为 fulfilled（`result.then(noop, noop)`），单个调用仍拿到自己的 rejection，后续写不会被卡死。
- **回归测试（已提交）**：`test/store.test.js` 新增 5 例——暂停 upsert + 并发 action 保留两者效果；两个并发 `applyAction` 按调用顺序串行；并发同 actionId 只执行一次状态机（validator 计数 1）且重放首结果；一次 rejection 不阻塞后续写；并发部分 `putSettings` 字段不丢。`test/sync.test.js` 新增 1 例：`sync.run()` 的 upsert 被暂停时 `store.applyAction` 排队，放行后 workflow/timeline 与平台字段同时保留，`lastSyncAt` 仍写入。

### 10.2 Important：保存 token 不持久化平台设置草稿（已修复）
